### 2.2 状態管理
- 外部の状態管理ライブラリは使わない。React の `useReducer` と Context で管理する。
- 状態は次の 2 種類に分ける。

| 種類 | 中身 | 保存先 |
|---|---|---|
| 永続状態 `PersistedState` | マスの記録、設定、演出済みライン | IndexedDB（操作ごとに保存） |
| 画面状態 `UiState` | 開いているシート・画面、選択中のマス、演出キュー | メモリのみ |

- 写真の Blob は状態に持たず、表示時に IndexedDB から読み出して `URL.createObjectURL` で表示する。サムネイルの URL は起動時にまとめて作り、差し替え時に `revokeObjectURL` する。
- 処理の流れ：操作 → reducer で新しい状態を計算 → IndexedDB に保存 → 保存に成功したら画面に反映。保存に失敗したら状態を戻してトーストを出す。

### 2.3 戻る操作の扱い
シートや全画面を開くときに `history.pushState({overlay: 名前})` を積む。`popstate` を受けたら一番上の重ね表示を閉じる。画面の × ボタンで閉じるときは `history.back()` を呼んで履歴をそろえる。

## 3. お題マスターデータ

`src/data/cells.ts` に定数として持つ（NFR-11）。

```ts
export type CellId = `r${1|2|3|4|5}c${1|2|3|4|5}`;

export interface CellMaster {
  id: CellId;
  title: string;      // お題名（要件定義書 3 章）
  emoji: string;      // 付録 A
  note?: string;      // 補足説明
  free?: true;        // 中央マスのみ
  rect: { x: number; y: number; w: number; h: number }; // 公式画像上の位置(px)
}
```

### 3.1 公式画像上のマスの位置（実測値）
公式カード画像（1500×1500px）の枠線を画素単位で測り、枠線の内側をマスの領域とした。枠線は手描きで太さが揺れるため、各マスの幅と高さは均一ではない。

| | 列 1 | 列 2 | 列 3 | 列 4 | 列 5 |
|---|---|---|---|---|---|
| x 開始 | 143 | 395 | 640 | 882 | 1103 |
| 幅 | 241 | 232 | 226 | 209 | 248 |

| | 行 1 | 行 2 | 行 3 | 行 4 | 行 5 |
|---|---|---|---|---|---|
| y 開始 | 208 | 464 | 708 | 952 | 1173 |
| 高さ | 247 | 234 | 229 | 210 | 240 |

- マス `rRcC` の矩形は（列 C の x 開始, 行 R の y 開始, 列 C の幅, 行 R の高さ）とする。
- 画面では、画像の表示幅 ÷ 1500 の倍率を掛けた位置に `CellButton` を置く。CSS では `left: calc(x / 1500 * 100%)` のように割合で指定し、画面サイズが変わっても追従させる。
- 補足説明は「トマソン」（r2c1）だけに付ける：「実用性がないのに何故か残されているドアやかいだんなどの事」

## 4. データモデルと IndexedDB

### 4.1 型
```ts
interface CellRecord {
  id: CellId;
  achieved: boolean;
  achievedAt?: string;   // ISO 8601
  memo?: string;         // 最大 100 文字
  hasPhoto: boolean;
  photoUpdatedAt?: string;
}

interface PhotoRecord {
  id: CellId;
  full: Blob;   // JPEG 長辺 1280px
  thumb: Blob;  // JPEG 240×240 正方形
}

interface Meta {
  schemaVersion: 1;
  displayMode: 'official' | 'text';
  introSeen: boolean;
  celebratedLines: LineId[];   // 演出済みのライン
  masterCelebrated: boolean;   // おでかけマスター演出済みか
  createdAt: string;
}
```

### 4.2 IndexedDB のスキーマ
データベース名 `odekake-bingo`、バージョン 1。ライブラリは `idb` を使う。

| ストア | キー | 値 | 件数 |
|---|---|---|---|
| `cells` | `id` | `CellRecord` | 25 |
| `photos` | `id` | `PhotoRecord` | 0〜25 |
| `meta` | 固定キー `'meta'` | `Meta` | 1 |

- 初回起動時（`meta` が無いとき）に、25 件の `CellRecord` を作る。中央 `r3c3` だけ `achieved: true`、`achievedAt` は作成日時にする。
- 1 回の操作で複数のストアを変える場合（例：取り消しで `cells` と `photos` を変える）は、1 つのトランザクションで行う。
- 将来スキーマを変えるときは、`upgrade` コールバックと `schemaVersion` で移行する。

### 4.3 永続保存の要求
初回起動時に `navigator.storage.persist()` を呼ぶ。拒否されても動作は続け、S-08 にエクスポートを勧める文を表示する。

## 5. ビンゴ判定

### 5.1 ライン定義
```ts
type LineId = `row${1|2|3|4|5}` | `col${1|2|3|4|5}` | 'diag1' | 'diag2';
// diag1: r1c1→r5c5、diag2: r1c5→r5c1
const LINES: Record<LineId, CellId[]> = { /* 12 本、各 5 マス */ };
```

### 5.2 処理
```ts
completedLines(achieved: Set<CellId>): LineId[]
  → LINES のうち、5 マスすべてが achieved に含まれるもの

newLines(completed: LineId[], celebrated: LineId[]): LineId[]
  → completed にあって celebrated に無いもの
```

- 「見た！」を押した後に `completedLines` を計算する。`newLines` が 1 本以上あれば S-04 の演出を出し、そのラインを `celebratedLines` に追加する。2 本同時でも演出は 1 回（基本設計 S-04）。
- 取り消した後に `completedLines` を計算し直し、揃わなくなったラインを `celebratedLines` から外す。もう一度揃えたら再び演出が出る。
- 25 マスすべてが達成になり、`masterCelebrated` が false なら S-05 を出して true にする。取り消しで 25 マス未満になったら false に戻す。
- 中央マスは常に達成なので、判定の特別扱いは不要。

## 6. 写真の処理

### 6.1 取り込み
- 「写真を撮る」は `<input type="file" accept="image/*" capture="environment">`、「写真を選ぶ」は `capture` なしの input を使う。
- iOS の HEIC は、ブラウザが input の時点で JPEG に変換して渡すことを前提にする。デコードに失敗したら「この写真は読み込めませんでした」と表示する。

### 6.2 縮小と EXIF 除去
1. `createImageBitmap(file, { imageOrientation: 'from-image' })` でデコードする。写真の向きをここで反映する。
2. 長辺が 1280px を超えるなら、縦横比を保って 1280px に縮小し、Canvas に描く。
3. `canvas.toBlob('image/jpeg', 0.82)` で書き出す。300KB を超えたら品質を 0.7 → 0.6 と下げて再書き出しする（NFR-07）。
4. サムネイルは中央を正方形に切り抜き、240×240、品質 0.8 で作る。

- Canvas に描き直した画像には元の EXIF が残らない。そのため位置情報も消える（FR-05、NFR-08）。
- 処理中は CellSheet にスピナーを出し、ボタンを無効にする。

### 6.3 達成との関係
写真を撮る・選ぶと、未達成のマスなら同時に達成にする（「写真を撮って見た！」）。

## 7. シェア画像の生成

### 7.1 共通

**印と枠の共通ルール**（画面のカード表示 S-01 とシェア画像の両方に適用する。2026-11-22 試作を見て決定）

| 要素 | ルール |
|---|---|
| スタンプ | マスの右下に、マスの短辺の 50% の大きさで押す。マスの縁から 4px 内側。角度はマスごとに −0.15〜+0.15rad の範囲で固定的に変える（手で押した感じを出す）。写真のあるマスにも押す |
| 写真サムネイル（画面のみ） | マスの左上に、マスの短辺の 40% の大きさで重ねる。白の 2px 縁取り付き。スタンプと重ならない |
| 揃ったラインの枠 | ラインに含まれる各マスを、ゴールド `#FFC21A` の 6px の線で囲む。カードの絵の上でも見えるよう、外側に紫紺 `#3C3557` の 2px の縁取りを付ける。ベースカラーのピンクとは区別する |

- 1080×1350px の Canvas に描き、`toBlob('image/png')` で書き出す。
- 描画前に `document.fonts.load()` で見出し用フォントの読み込みを待つ。
- 公式画像とスタンプは `<img>` で読み込んでから描く。同じオリジンなので Canvas が汚染されず書き出せる。

### 7.2 カード版（FR-10）
| 領域 | 位置（px） | 内容 |
|---|---|---|
| ヘッダー | y 0〜120 | 背景グラデーション。「トコトコおでかけビンゴ」と「🎉 N ビンゴ ✅ M/25」 |
| カード | y 120〜1200 | 公式画像を 1080×1080 に縮小して描く。達成マスにスタンプ、揃ったラインのマスに枠を描く（§7.1 の共通ルール） |
| フッター | y 1200〜1350 | ハッシュタグと「非公式ファンツール『おでかけビンゴ帳』で作成」 |

### 7.3 写真入り版（FR-11）
- ヘッダー（y 0〜120）とフッター（y 1200〜1350）はカード版と同じ。
- y 120〜1200 の領域に 5×5 のマスを描く。各マスの下にお題名（17px）を添える。
- 写真があるマスはサムネイルではなく、元の写真から正方形に切り抜いて描く（画質のため）。
- 写真がないマスは、公式画像のそのマスの矩形（§3.1）を切り出して描く。未達成なら白の半透明（不透明度 0.6）を重ねて薄くする。
- 達成マスには、写真の有無にかかわらずスタンプを押す。揃ったラインのマスには枠を描く（§7.1 の共通ルール）。
- 1 マスは 176px 四方、マス間の余白は 12px、お題名の行は 24px とする（5 行で 1048px に収まる）。

### 7.4 共有（FR-12）
```
const file = new File([blob], 'odekake-bingo.png', { type: 'image/png' });
if (navigator.canShare?.({ files: [file] })) {
  await navigator.share({ files: [file], text: 投稿文 });
} else {
  // 代替：画像の保存ボタンと X で投稿ボタンを主ボタンにする
}
```
- 画像の保存：`<a download="odekake-bingo-YYYYMMDD.png">` に Blob URL を渡してクリックする。
- X で投稿：`https://x.com/intent/post?text=<投稿文を URL エンコード>` を新しいタブで開く。
- `navigator.share` がユーザーにキャンセルされた（`AbortError`）ときは何も表示しない。

### 7.5 投稿文
```
トコトコおでかけビンゴ {N}ビンゴ！（{M}/25マス）
#さなちゃんねるトコトコおでかけビンゴ
```
- N が 0 のときは「トコトコおでかけビンゴ 挑戦中！（{M}/25マス）」にする。
- 25 マス達成のときは「トコトコおでかけビンゴ 全マス達成でおでかけマスター！」にする。
- 利用者はシェア画面で投稿文を編集できる。編集内容は保存しない。

## 9. エクスポート / インポート

### 9.1 zip の中身
```
odekake-bingo-YYYYMMDD.zip
├─ data.json
└─ photos/
   ├─ r1c1.jpg        元写真（長辺 1280px）
   ├─ r1c1_thumb.jpg  サムネイル
   └─ ...
```

```jsonc
// data.json
{
  "app": "odekake-bingo",
  "formatVersion": 1,
  "exportedAt": "2026-11-23T10:00:00+09:00",
  "meta": { /* Meta */ },
  "cells": [ /* CellRecord × 25 */ ]
}
```

- zip の作成と展開には `fflate` を使う。JPEG はすでに圧縮されているので、無圧縮（store）で格納する。
- 共有は §7.4 と同じ方法で行う（Web Share でファイルを渡すか、ダウンロード）。

### 9.2 インポートの検証
次のいずれかに当てはまれば読み込みを中止し、今のデータは変更しない。
- zip として開けない、または `data.json` が無い
- `app` が `odekake-bingo` でない、または `formatVersion` が対応していない
- `cells` が 25 件でない、または未知の `id` がある
- `hasPhoto: true` のマスに対応する写真ファイルが無い
- ファイルサイズが 100MB を超える

検証を通ったら D-03 で内容（達成数、写真の枚数、エクスポート日時）を見せる。了承されたら、3 つのストアを 1 つのトランザクションで全件置き換える。

## 10. 代替表示（C-05）

- `Meta.displayMode` が `'text'` のとき、`TextCard` で文字と絵文字のカードを描く。印はオリジナル画像（`public/original/mark.svg`：コーラルピンクの手描き風の丸）を使う。
- シェア画像も同じ方針で描く（公式画像の代わりに文字マス、スタンプの代わりにオリジナル印）。
- ビルド時の環境変数 `VITE_OFFICIAL_ASSETS=false` を指定すると、公式素材をビルドから外し、表示方式を `'text'` に固定する。公式から指摘を受けた場合は、この設定で再配置するだけで対応できる。

## 11. デザイントークン

`src/styles/tokens.css` に CSS 変数として定義する。コントラスト比は WCAG 2.1 の計算式で確認した。

| 変数 | 値 | 用途 | コントラスト |
|---|---|---|---|
| `--color-text` | `#3C3557` | 本文 | 白地で 11.4、背景ラベンダーで 9.2（AA 適合） |
| `--color-accent` | `#FF8484` | 主ボタンの地、装飾（揃ったラインには使わない） | — |
| `--color-on-accent` | `#3C3557` | 主ボタン上の文字 | コーラル地で 4.8（AA 適合） |
| `--color-accent-strong` | `#C9405A` | 白地に置くコーラル系の文字（ビンゴ数など） | 白地で 4.8（AA 適合） |
| `--color-bg-from` / `--color-bg-to` | `#E9E4FA` / `#E3F1FC` | 画面の背景グラデーション | — |
| `--color-surface` | `#FFFFFF` | シート、カード、ダイアログの面 | — |
| `--color-line` | `#8A9CC4` | 装飾の枠線 | — |
| `--color-bingo` | `#FFC21A` | 揃ったラインの枠。外側に `--color-text` の縁取りを付けて使う | 非テキスト（紫紺の縁取りで、どの背景でも 3.0 以上を確保） |
| `--color-line-strong` | `#6B7DA8` | ボタンや入力欄など操作できる部品の枠線 | 白地で 4.1（UI 部品の基準 3.0 に適合） |
| `--radius` | `16px`（ボタン 999px） | 角丸 | — |
| `--border` | `2px` | 輪郭線の太さ | — |

- 白地に `#FF8484` の文字はコントラストが 2.4 と不足するため、文字には使わない。
- フォントは npm の `@fontsource/ibm-plex-sans-jp`（400、700）と `@fontsource/m-plus-rounded-1c`（700）を使う。アプリに同梱して自分のサイトから配信し、Google への通信を発生させない（NFR-08）。

## 14. エラー処理

| 状況 | 検出方法 | 表示 | 状態 |
|---|---|---|---|
| 保存容量不足 | IndexedDB の `QuotaExceededError` | トースト：「写真を保存できませんでした。容量を空けるか、写真なしで記録してください」 | 写真なしで達成だけ保存する |
| IndexedDB が使えない（プライベートブラウズ等） | 起動時の open 失敗 | 画面上部に常時の警告：「この状態では記録が保存されません」 | メモリ上で遊べる |
| 写真が読めない | `createImageBitmap` の例外 | トースト：「この写真は読み込めませんでした」 | 変更なし |
| インポート不正 | §9.2 の検証 | ダイアログ：理由を表示 | 変更なし |
| 共有の失敗 | `navigator.share` の `AbortError` 以外の例外 | トースト：「共有できませんでした。画像を保存してから投稿してください」 | 変更なし |

カメラの許可を拒否されたかどうかは、ファイル入力の方式ではブラウザから分からない。そのため、写真の取り込みがキャンセルされたときは何も表示しない。

## 15. アクセシビリティ

- カードは `role="grid"`、各マスは `<button>` にする。`aria-label` は「{お題名}、{達成済み / 未達成}{、写真あり}」とする。
- ビンゴ数・達成数は `aria-live="polite"` で読み上げる。
- `prefers-reduced-motion: reduce` のときは、光る演出とシートのアニメーションを止める。
- 文字サイズは端末設定に追従させる（`rem` 指定）。

### 16.2 E2E テスト（Playwright、iPhone 13 と Pixel 7 のエミュレーション）
