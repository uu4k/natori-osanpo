## 3. E2E テスト（Playwright）

実行環境：Chromium（Playwright 1.65）。機種は「iPhone 13 の画面サイズ」と「Pixel 7」の 2 種類。本番ビルドを `vite preview` で配信して実行した。

| # | シナリオ（詳細設計 §16.2） | 結果 |
|---|---|---|
| 1 | 初回のはじめにが出て、2 回目以降は出ない | 成功 |
| 2 | 見た！でスタンプが付き、達成数が増える | 成功 |
| 3 | 1 行揃えるとビンゴ演出 → シェア画面へ移れる。揃った列に枠が付く | 成功 |
| 4 | 写真を選ぶとサムネイルとスタンプが出る。保存した写真とサムネイルに EXIF（偽の位置情報入り）が残らない。300KB 以下 | 成功 |
| 5 | メモが再読み込み後も残る | 成功 |
| 6 | 写真ありの取り消しで確認が出て、未達成に戻る | 成功 |
| 6' | 中央マスは取り消せない（追加） | 成功 |
| 7 | シェア画像（カード版・写真入り版）が 1080×1350 で作られ、投稿文にハッシュタグが入る | 成功 |
| 8 | エクスポート → リセット → インポートで元の状態（達成・写真・メモ）に戻る | 成功 |
| 8' | 不正なファイルのインポートは拒否され、データが変わらない（追加） | 成功 |
| 9 | ブラウザの戻る操作でシートが閉じる | 成功 |
| 10 | オフラインで再読み込みしてもカードが表示され、記録できる | 成功 |
| 11 | 表示を「文字」にすると公式画像が表示されない | 成功 |

**目視確認**（内蔵ブラウザ、375×812 のモバイル表示）：はじめに、カード画面、マス操作シート、ビンゴ演出（揃った列のゴールド枠と光）、シェア画面を確認した。

**公式素材なしビルド**：`npm run build:no-official` の出力に `official/` フォルダが含まれず、Service Worker のキャッシュ対象にも公式画像が入らないことを確認した。

## 4. 未解決・制約事項

| 区分 | 内容 |
|---|---|
| 未実施 | iOS Safari（WebKit）での自動テスト。Playwright の WebKit を導入していないため、iPhone は画面サイズのみの再現。実機確認で補う |
| 未実施 | Web Share API による X アプリへの画像共有。PC のヘッドレスブラウザでは使えないため、代替（画像保存＋X 投稿画面）の経路のみ自動テストした |
| 未実施 | Lighthouse による PWA・アクセシビリティの採点 |
| 警告 | oxlint の `only-export-components`（`useStore` をコンポーネントと同じファイルから export）。開発時のホットリロードにのみ影響し、動作には影響しない |
| 依存関係 | `npm audit` で中程度の脆弱性 2 件（vite-plugin-pwa が使う workbox-build 内の glob / minimatch）。ビルド時にのみ使うツールで、公開されるアプリには含まれない |
| 性能 | フォントの CSS が 509KB（gzip 後 242KB）と大きい。日本語フォントの文字範囲ごとの定義が多いため。初回表示の目標（4G で 3 秒）は実機で確認する |

## 5. 設計からの変更点

| 箇所 | 変更内容 | 理由 |

| ビンゴ演出（S-04） | 演出が出たらマス操作シートを自動で閉じ、演出の箱を画面下部に表示する | シートでカードが隠れ、揃った列の光が見えなかったため |
| 依存ライブラリ（§12） | React 19、Vite 8、TypeScript 7、vite-plugin-pwa 2、Vitest 5 | 実装時点の最新安定版を採用した |
| 中央マスの補足 | 「出発したら達成！」を補足説明として表示 | — |
